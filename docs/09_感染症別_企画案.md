## 1. 背景

現行アプリの入口は「内服薬／注射薬／菌種別／その他」の4つで、いずれも **薬剤または菌から引く** 構成である。
実際の診療では「肺炎らしい」「下痢で来た」という **感染症から引きたい** 場面が多く、その入口がない。
本企画はこの入口を新設する。

## 2. 原典の実態（当初の想定との差異）

**当初案は「両文書とも疾患別で、肺炎・尿路感染の章がある」という前提で書いたが、実物は違った。**
ここが本改訂の中心である。

### 2.1 外来編（101頁）— 疾患別。感染症別レーンの本体になる

| 章 | 対象 | 収録疾患 |
|---|---|---|
| 4. 急性気道感染症 | 成人・学童期以降の小児 | 感冒、急性鼻副鼻腔炎、急性咽頭炎、急性気管支炎 |
| 5. 急性下痢症 | 同上 | 急性下痢症 |
| 9. 小児の急性気道感染症各論 | 乳幼児 | 感冒・急性鼻副鼻腔炎、急性咽頭炎、クループ症候群、急性気管支炎、急性細気管支炎 |
| 10. 急性下痢症 | 乳幼児 | 急性下痢症 |
| 11. 急性中耳炎 | 乳幼児 | 急性中耳炎 |
| 12. 皮膚軟部組織感染症 | 乳幼児 | 伝染性膿痂疹、蜂窩織炎、癤・皮下膿瘍 |

**好都合な点**: 外来編は「成人・学童期以降」と「乳幼児」で編を分けている。
これは**既存アプリの「成人／小児」切り替えとそのまま一致する**（新しい出し分けの仕組みが要らない）。

### 2.2 入院編（56頁）— 疾患別ではない

章立ては「4. 入院患者の感染症に対する基本的な考え方 (1)診断・治療のプロセス (2)マネジメント」＋付録で、
**疾患ごとの章が存在しない**。中身は横断的な原則と表である。

### 2.3 「肺炎」「尿路感染」はどこにあるか

ご要望にあった肺炎・尿路感染は、**入院編の表5（治療期間の早見表）の行として登場する**。

> 表5「入院中によく遭遇する感染症の短期治療期間の例」
> 非重症の市中肺炎 / VAPを含む院内肺炎 / 女性の非複雑性膀胱炎 / 女性の非複雑性腎盂腎炎・CAUTI /
> 男性の有熱性UTI / 非重症の蜂窩織炎 / 非複雑性CRBSI / 急性胆嚢炎 / 急性化膿性胆管炎 /
> 消化管穿孔による腹膜炎・術後腹腔内感染症 / 椎体椎間板炎 / 菌血症 / 非複雑性黄色ブドウ球菌菌血症

つまり肺炎・UTI について本原典から出せるのは **治療期間と想定原因微生物まで**で、
**「第一選択はこれ」という経験的治療の推奨は載っていない**。

> **設計上の帰結（2026-08-28 改訂）**: 当初は「入院編は横断的な表として別に見せる」案としたが、
> **仕様（FR-100-5）により、感染症名を主キーとして情報を集約する方式に改めた。**
> 肺炎について本原典から出せるのは経験的治療の推奨ではなく
> **想定起炎菌（表2）と治療期間（表5）**だが、それらを1画面に集めれば
> 「肺炎を引いたら肺炎のことが分かる」という要件は満たせる。→ §4

## 3. 編集方針：何を載せ、何を載せないか

### 3.1 抽出の原則：表は残す、本文は要約する

原典から拾う際の優先順位を、**元の書式そのもの**で判断する。

| 原典での書かれ方 | 扱い | 理由 |
|---|---|---|
| **表・一覧にまとめられた記載** | **重要度が高い。構造を保ったまま残す** | 著者が「一覧で引けるべき」と判断した項目であり、そのまま処方判断に使われる |
| 本文（地の文）の記載 | **できるだけ要約する。1〜2行に圧縮** | 背景説明・根拠・引用文献の記述が大半で、ベッドサイドでは読まれない |
| 図・フローチャート | 原則載せない（ページ参照のみ） | 小画面で判読できず、要約すると意味が変わる危険がある |

補足：

- 表を残す＝**画像として貼るのではなく、各セルを構造化データにする**（§5）。
  画像だと薬剤詳細へリンクできず、検索にも乗らない
- **本文中でも「判断が変わる情報」は要約せず残す。** 特に次は必ず残す:
  - 具体的な用量・期間（例: 外来編 p.30「アモキシシリン 1回500mgを1日3回 5〜7日間」）
  - **数値情報（パーセンテージを含む）**（FR-100-4）。本文中に埋もれていても拾い上げる。例:
    - 急性ウイルス性上気道感染症のうち細菌性鼻副鼻腔炎の合併は **2%未満**（外来編 p.24）
    - 急性咽頭炎で GAS が原因なのは成人の **約10%**、日本の20〜59歳の急性扁桃炎では **約30%**（同 p.25）
    - 急性気管支炎の原因は **90%以上がウイルス**（同 p.27）
    - 感冒への抗菌薬投与で副作用が **プラセボの2.62倍**（95%CI 1.32〜5.18）（同 p.28）
    - 急性鼻副鼻腔炎は無治療でも **1週間で46%、2週間で64%が治癒**。抗菌薬で改善が早まるのは
      100人中 **5〜11人**（同 p.29）
    → これらは「抗菌薬を出さない」判断を患者に説明する際にそのまま使える。**本アプリで最も価値が高い部分**
  - 禁忌・警告、「抗菌薬を投与しない」という推奨そのもの
  - 適応外使用に関する注記（例: 同 p.30「アモキシシリンの鼻副鼻腔炎は薬事承認されていない」）
    → **既存の適応外使用機能と接続できる**
- 重症度スコア（表3・表4等）は表なので**表として載せる**。ただし Phase 1 では**自動計算はしない**
  （入力UIが増え §3.5 の分量目安を超える）。自動計算は将来の別機能とする

### 3.3 用語集（両文書の冒頭）の扱い

両文書とも冒頭に大きな「抗菌薬の種類」対応表（分類・一般名・商品名・略語）がある。
**これは載せない。**既存アプリの薬剤データが同じ情報を当院の採用状況込みで持っており、二重管理になる。

### 3.4 疾患ページに載せる項目（外来編の疾患、1件あたり最大7項目）

| # | 項目 | 備考 |
|---|---|---|
| 1 | 抗菌薬を使うか否かの推奨 | **本手引きの主眼。「投与しない」も明確に出す** |
| 2 | 抗菌薬の適応となる条件 | 表があれば表のまま |
| 3 | 推奨薬・用量・期間 | 薬剤名タップ →**既存の薬剤詳細へ** |
| 4 | 想定起炎菌 | 菌名タップ →**既存の菌種別画面へ** |
| 5 | 重症度分類・判定基準 | 表があれば表のまま |
| 6 | レッドフラッグ／注意所見 | |
| 7 | 原典ページ | `source` として全レコードに必須 |

### 3.5 載せない

- 疫学・病態生理・策定の経緯の解説文
- 鑑別診断のフローチャート、画像所見
- 引用文献の羅列（外来編は3章・7章・14章が丸ごと文献）
- 既存の薬剤詳細画面に既にある情報（腎機能別用量、TDM目標値、AWaReバッジ、申請要否）
  → **二重管理は片方だけ古くなる事故を招く。**薬剤詳細に一本化しリンクで送る

### 3.6 分量の目安

1疾患あたり **スマートフォン1〜2画面**（スクロール2回以内）を上限とする。
超える場合は疾患の切り方が粗いと判断して分割する（表は間引かない）。

## 4. 画面構成（2026-08-28 改訂：感染症名で集約する方式）

### 4.1 基本方針：原典の章立てを画面に写さない

原典は外来編＝疾患別、入院編＝総論と構造が異なるが、
**その違いを画面構成に持ち込まない**（FR-017-3）。
感染症名を主キーにし、**両編に散らばった記載をアプリ側で束ねる。**

例：「肺炎」を引いたときに集まるもの

| 項目 | 出典 |
|---|---|
| 想定起炎菌（緑膿菌、黄色ブドウ球菌、Enterobacter cloacae、肺炎桿菌、口腔内常在菌） | 入院編 表2 |
| 治療期間（非重症の市中肺炎 3〜5日／VAPを含む院内肺炎 7〜8日） | 入院編 表5 |
| 経口スイッチの基準 | 入院編 表8・表9 |

「蜂窩織炎」であれば外来編（小児・皮膚軟部組織感染症）と入院編 表5（治療期間 5〜6日）の
**両方から集まる**。原典のどこに書かれていたかは利用者には関係がない。

### 4.2 遷移

```
オープニング（大項目 4→5ボタン）
├─ 内服薬 / 注射薬 / 菌種別
├─ 感染症別   ← 新設
│   ├─ 感染症名の入力欄（既存の薬剤検索と同じ形）
│   └─ 部位別カテゴリ
│        ├─ 気道・耳鼻科  … 感冒／急性鼻副鼻腔炎／急性咽頭炎／急性気管支炎／
│        │                  クループ症候群／急性細気管支炎／急性中耳炎
│        ├─ 呼吸器（肺炎） … 市中肺炎／院内肺炎・VAP
│        ├─ 尿路          … 膀胱炎／腎盂腎炎・CAUTI／男性の有熱性UTI
│        ├─ 消化器        … 急性下痢症／胆嚢炎／胆管炎／腹膜炎・術後腹腔内感染
│        ├─ 皮膚軟部組織   … 伝染性膿痂疹／蜂窩織炎／癤・皮下膿瘍
│        └─ 血流・その他   … 菌血症／CRBSI／椎体椎間板炎
│             └─ 感染症詳細 ─(薬剤名タップ)→ 既存の薬剤詳細
│                          └(菌名タップ)  → 既存の菌種別画面
└─ その他
```

- 既存レーンと同じ **3階層** に揃える
- **成人／小児**は既存の切り替えをそのまま使う（外来編が同じ区分で編を分けているため相性がよい）
- ボタンは既存の `top-btn` / `top-grid` を流用し、新規CSSは最小限にする

### 4.3 収録項目は疾患ごとに可変とする

疾患によって原典から取れる項目数は大きく異なる。
**取れた項目だけを出し、無い欄は表示しない**（FR-017-3）。「記載なし」を並べない。

| | 抗菌薬の要否 | 推奨薬 | 起炎菌 | 治療期間 | 重症度表 |
|---|:-:|:-:|:-:|:-:|:-:|
| 感冒（外来編） | ● | 投与しない | — | — | — |
| 急性鼻副鼻腔炎（外来編） | ● | ● | — | ● | ● |
| 肺炎（入院編） | — | — | ● | ● | — |
| 蜂窩織炎（両編） | ● | ● | — | ● | — |

肺炎のように経験的治療の推奨が原典に無い疾患では、**無理に補わない。**
「本手引きには経験的治療の記載がない」ことを明示し、当院の薬剤詳細へ送る。

### 4.4 却下した案

| 却下案 | 理由 |
|---|---|
| 疾患詳細の中で「入院／外来」をタブ切替 | **入院編に疾患別の章が無く、タブの中身を作れない**（§2.2） |
| オープニングで先に「入院／外来」を選ばせる | 既存の「成人／小児」と二重になり階層が深くなる。**利用者は原典の編を意識しない**（§4.1） |
| 入院編を横断的な表のまま別立てで見せる | 「肺炎を引いたら肺炎のことが分かる」という要件（FR-100-5）を満たせない。**当初案を撤回**した |

## 5. データモデル案

### 5.1 型定義（`src/types.ts` に追加）

```ts
/** 原典の区分 */
export type StewardshipSource = "outpatient" | "inpatient";

/** 疾患のカテゴリ（外来編の章立てに対応） */
export type InfectionCategory =
  | "respiratory" | "gastrointestinal" | "otitis" | "skin_soft_tissue";

/** 原典で表になっていた記載の受け皿（§3.1「表は残す」を満たすために持つ） */
export type InfectionTable = {
  caption: string;
  headers: string[];
  rows: string[][];
  note?: string;
  source: Source;
};

/** 推奨される薬剤 */
export type RecommendedDrug = {
  /**
   * 当院採用薬に該当する場合の Drug.id。
   * 原典が挙げる薬でも当院データに無いものがある（セフカペン・セフジトレン・
   * テビペネム等の経口第3世代セフェム／経口カルバペネム）ため null を許す。
   * null のときはリンクを張らず薬剤名のテキストのみ表示する。
   */
  drugId: string | null;
  /** drugId が null のときに表示する名称 */
  label: string;
  /** 原典どおりの用量表記。用量の正はあくまで薬剤詳細側 */
  dosage?: string;
  duration?: string;
};

export type InfectionEntry = {
  id: string;
  name: string;
  aliases: string[];
  category: InfectionCategory;
  origin: StewardshipSource;
  /** 対象集団。既存の PatientMode をそのまま使う */
  populations: PatientMode[];
  /** 抗菌薬投与の要否についての推奨（本手引きの主眼） */
  recommendation: string;
  /** 抗菌薬の適応となる条件 */
  indication?: string[];
  /** 推奨薬。抗菌薬非推奨の疾患では空 */
  drugs: RecommendedDrug[];
  /** 想定起炎菌。既存の Organism.id で持つ */
  likelyOrganismIds?: string[];
  /** 原典の表をそのまま残したもの */
  tables?: InfectionTable[];
  /** 本文から要約した、判断に効く注記（禁忌・警告は要約せず原文のまま） */
  keyPoints?: string[];
  source: Source;
};
```

### 5.2 なぜ薬剤を ID で持つのか（本企画の肝）

ご要望の「**抗生剤治療についての記載が出てきたら薬剤別解説へ移動する**」は、
薬剤を `drugId: "amoxicillin"` の形で持てば自動的に満たされる。

- 表示名は `DRUG_BY_ID` から引くので **表記ゆれが起きない**
- 存在しない薬剤IDを書けば `validate-data.mjs` で**ビルドが落ちる**（リンク切れが起きない）
- **実装の前例がすでにある**: アンチバイオグラムの略号タップ → 薬剤詳細
  （`src/components/OrganismDetail.tsx:114-122`、`DRUG_BY_ABBR` と `onOpenDrug`）。
  同じ仕組みを `DRUG_BY_ID` で使うだけで、**新規の仕組みは不要**

### 5.3 当院に採用の無い薬剤の扱い（実データで確認済み）

原典が挙げる薬剤を当院データと突合した結果:

## 8. 確認事項

### 8.1 【要判断】規程上の位置づけ

現行の要件定義に次の定めがある。

> **NFR-012**: 公開前にプログラム医療機器（SaMD）該当性を薬剤部・法務で確認する。
> **院内文書の閲覧支援に留め、診断・治療方針の提示は行わない**（`docs/02_要件定義書.md:333`）

本機能は「疾患別に抗菌薬の要否と推奨薬を示す」ため、この線に触れる。
ただし当初の想定より状況は良い：

- 原典が**厚労省の公表資料**であり、当院の内部判断ではなく**国の手引きの引用**として位置づけられる
- 本手引きの主眼は**「抗菌薬を使わない」ことの推奨**であり、治療方針の積極的提示とは性格が異なる

判断をお願いしたい点：

- (a) 「厚労省手引きの閲覧支援」として NFR-012 の範囲内と整理してよいか
- (b) 薬剤部・法務／感染対策委員会への確認は必要か
- (c) 表示上の但し書き案：
  「本項は**厚生労働省『抗微生物薬適正使用の手引き 第四版』の記載を要約したもの**であり、
  個々の患者の治療方針を示すものではない。最終的な判断は主治医が行う。
  当院での用量・採用状況・申請ルールは薬剤詳細画面を参照」

### 8.2 著作権（懸念はほぼ解消）

原典は厚生労働省の公表資料であり、当院の内部文書でも商用ガイドラインでもない。
政府の公表資料は出典明示のうえで利用できるのが原則のため、**一般公開されている本アプリへの収載は問題になりにくい**。
実務上の対応として次を行う（`docs/02_要件定義書.md:378` の未解決事項とは別件として扱える）：

- 全画面に出典（厚生労働省・手引き名・版・頁）を明示する
- 要約であり原文そのものではない旨を明記する（§8.1(c)）
- 念のため、公開前に**利用規約の条件（出典表示の書式）を1度確認する**

### 8.3 内容に関する確認

- **入院編の見せ方**（§4.1）: 疾患別ではなく「横断的な表」として出す方針でよいか
- **肺炎・尿路感染**: 本原典からは治療期間しか出せない（§2.3）。
  経験的治療まで載せたい場合は**別の出典が必要**だが、その調達をどうするか
- 用量が原典と当院の薬剤データで食い違った場合、**どちらを正とするか**
  （案: **当院の薬剤詳細を正**とし、感染症画面は選択薬・要否・期間のみ示す）
