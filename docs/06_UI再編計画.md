# UI再編計画（第2版UI）

- 版: 1.0（計画）
- 作成日: 2026-08-27
- 対象: 起動導線・薬剤検索・AWaRe絞り込み・TDM導線・表組みレイアウト
- 前提: Phase 0〜2 実装済み（薬剤74件／菌40件／疾患83件／適応外68件／アンチバイオグラム80行）

## 0. この再編の要旨

現行UIは **起動直後に「成人／小児」を選ばせる**構造（FR-000）を最優先原則としていた。
これを取りやめ、**原典の章立てに沿った4つの大項目**を入口にする。

| | 現行 | 再編後 |
| --- | --- | --- |
| 入口 | 成人／小児の2択（必須・既定値なし） | 内服薬／注射薬／菌名／周術期 の4択 |
| 成人・小児 | アプリ全体のモード。片方の用量しか表示しない | 患者条件の一属性。薬剤詳細で両方を明示的に並記 |
| 薬剤の絞り込み | 全74剤を横断検索のみ | 剤形レーンで分割 → 内服はAWaRe分類でも絞れる |
| TDM | 薬剤詳細の下部にリンク（既存） | 導線を上部へ引き上げ、往復できるようにする |

### なぜ「成人／小児を入口にする」のをやめるのか

当初の設計原則は「入口で患者集団を確定し、誤参照を構造的に防ぐ」だった。しかし運用上、次の問題がある。

1. **原典の構造と一致しない。** 原典は「注射薬／内服薬／菌／周術期」で章立てされており、成人・小児は各章の中の区分にすぎない。入口で分けると原典と目次構造がずれ、「マニュアルのどこを見ているか」が利用者から見えなくなる。
2. **大半の利用者にとって毎回同じ答えを選ばされる。** 成人病棟の医師は起動のたびに「成人」を押すことになり、最初の1タップが常に無駄になる。コンセプトの「3タップ以内」を1タップ分損している。
3. **薬剤を探す前に患者属性を聞くのは順序が逆。** 「セフェピムを調べたい」という意図に対し、患者集団の確定が先に来る。調べたい対象（剤形・菌・術式）を先に選ぶほうが自然。
4. **モード切替の副作用が大きい。** 現行は小児用量を見るとアプリ全体のモードが切り替わる（`onSwitchMode`）。閲覧のつもりの操作がグローバル状態を書き換えるのは事故のもとで、戻し忘れると以降ずっと誤った集団の用量を見続けることになる。

### 安全性の担保をどう置き換えるか（重要）

旧FR-000の狙いである「成人量と小児量の取り違え防止」は、**構造的分離から明示的表示へ**方式を変える。
削るのではなく、置き換える。実装時に以下を必須要件とする。

- 成人用量と小児用量は**同じセクション内に混在させない**。必ず別セクション・別見出し・別背景色で描画する。
- 各セクション見出しに「成人」「小児」を**常に**書く（患者条件が未入力でも省略しない）。
- 患者条件に年齢が入っていれば、該当する側のセクションを強調し、他方を淡色化＋折りたたむ。
- **小児用量は体重未入力なら mg/kg 表記のみ**とし、絶対量(mg)を出さない（旧FR-000-5を維持）。
- 原典に小児量の記載がない薬剤は「原典に小児の投与量の記載なし」と明示し、推定値を出さない（旧FR-000-6を維持）。

> **要レビュー**: この方式変更は本アプリで唯一の安全性設計の後退リスクを含む。実装後、薬剤部・感染制御管理室のレビューを受けるまで院内公開しないこと。判断材料として、実装後に「成人／小児が同時に見える状態」のスクリーンショットを添えてレビュー依頼する。

## 1. 画面構造（再編後）

```
ホーム
├─ [内服薬]  ─→ 薬名入力欄 ─→ AWaRe絞り込み ─→ 薬剤一覧 ─→ 薬剤詳細 ─→ TDM設計
├─ [注射薬]  ─→ 薬名入力欄 ─→ 系統絞り込み  ─→ 薬剤一覧 ─→ 薬剤詳細 ─→ TDM設計
├─ [菌名]    ─→ 菌名入力欄 ─→ 菌一覧 ─→ 菌詳細（アンチバイオグラム）
├─ [周術期]  ─→ 領域選択 ─→ 推奨薬・1回量・投与期間
│
├─ 患者条件（ヘッダーから開閉。年齢・性別・体重・身長・Cr・eGFR・腎代替療法）
└─ その他の機能（従属セクション。適応外使用／TDM設計／採用薬一覧／アナフィラキシー／
                 曝露後予防／PCG持続静注／小児体重／適正使用指針・AWaRe／AMR対策）
```

### 1.1 大項目4ボタン

原典の章立てに対応する。ホーム最上部に大きめのタイルで配置する。

| ボタン | 対象 | 件数 | 遷移先 |
| --- | --- | --- | --- |
| 内服薬 | `adult.po` または `pediatric.po` を持つ薬剤 | 43剤 | 内服薬レーン |
| 注射薬 | `iv` / `im` / `inhalation` を持つ薬剤 | 42剤 | 注射薬レーン |
| 菌名 | 菌マスタ全件 | 40件 | 菌検索 |
| 周術期 | 周術期予防抗菌薬 | 15領域 | 既存の `SurgicalProphylaxis` |

- **内服と注射の両方を持つ薬剤が12剤ある**（レボフロキサシン等）。両レーンに重複して出す。
  ただし各レーンでは**そのレーンの剤形の用量を主表示**とし、他剤形は詳細画面で併記する。
  1剤1ページの原則（設計原則2）は維持し、詳細画面は分けない。
- 剤形をどちらも持たない薬剤が1剤ある（要調査。`validate-data.mjs` に検査を追加し、
  どちらのレーンにも出ない薬剤を検出できるようにする）。

### 1.2 内服薬レーン

利用者指定の順序どおりに配置する。

1. **薬名入力欄**（最上部）
   - プレースホルダ: 「商品名・一般名で検索（例：クラビット、レボフロキサシン、LVFX）」
   - 既存の `searchDrugs` を流用し、**内服の用量を持つ薬剤に限定**して結果を返す。
   - 入力があればAWaRe絞り込みより検索結果を優先表示する（入力欄が主、分類が副）。

2. **AWaRe分類の簡単な説明**
   - 原典 p.74 の記述を要約して2〜3文で提示する。全文は「適正使用指針・AWaRe」ページへのリンクで送る。
   - 記載必須: 「Accessを増やし、Watch・Reserveを減らすのがWHOの方針」「Access 60%以上が目標」
   - **注記必須**: AWaRe分類は原典では**内服薬に対してのみ**掲載されている（p.74）。注射薬レーンにこの絞り込みは置かない。

3. **分類ボタン → 対象薬剤の絞り込み**

| ボタン | 定義 | 該当数 |
| --- | --- | --- |
| Access | 原典p.74 のAccess欄 | 11剤 |
| Watch | 同 Watch欄 | 11剤 |
| Reserve | 同 Reserve欄 | 1剤（リネゾリド） |
| Not recommended | 同 Not recommended欄 | 1剤（アトバコン） |
| その他 | 原典のAWaRe表に記載のない内服薬 | 19剤 |

   - 「その他」19剤の内訳は**抗結核薬3・抗真菌薬7・抗ウイルス薬7・駆虫薬2**。
     WHOのAWaRe分類は抗菌薬（antibacterial）を対象とするため、これらが分類外なのは正常。
     ボタンの補助文言に「AWaRe分類は抗菌薬を対象とするため、抗真菌薬・抗ウイルス薬等は分類対象外です」と添える。
   - ボタンは複数選択可（トグル）。選択解除で全件に戻る。
   - 各ボタンに該当件数を表示する。

> **判断が必要な点**: ご指示は「Access / Watch / Reserve / その他」の4分類でしたが、原典p.74 には
> **Not recommended（アトバコン1剤）** の欄が実在します。これを「その他（分類中に記載のないもの）」に
> 混ぜると、*分類されていない薬* と *非推奨と分類された薬* が同じ箱に入り、原典の情報が失われます。
> このため上表では **5ボタン** を推奨案としています。4ボタンに寄せる場合は
> 「Reserve / Not recommended」を1ボタンに束ねる案（＝使用を最も抑えるべき群としてまとめる）が
> 次善で、「その他」に混ぜる案は採りません。実装前にご判断ください。

### 1.3 注射薬レーン

内服薬レーンと同じ骨格（入力欄が上、絞り込みが下）で、絞り込み軸だけを差し替える。

- 絞り込み: **系統**（`class`。β-ラクタム系／キノロン系／アミノグリコシド系／抗MRSA薬／抗真菌薬 等）
- 併せて表示するバッジ: 「要申請」「要コンサルト」「TDM対象」
- 採用注射薬一覧（規格・薬価・配合変化）への導線をレーン内に置く

### 1.4 菌名レーン / 周術期レーン

既存の `OrganismDetail` / `SurgicalProphylaxis` をそのまま遷移先にする。
入口が大項目ボタンに変わるだけで、中身の変更はしない（今回の再編スコープ外）。

## 2. CCr計算と用量提示（継続・変更なし）

ご指示のとおり**現行の仕組みを維持する**。以下は再確認であり、作り直さない。

- 身長・体重・年齢・性別・Cr から Cockcroft-Gault で CCr を自動計算（`src/lib/calc.ts`）
- 理想体重 IBW = 身長(m)² × 22、補正体重 AdjBW = IBW + 0.4 ×(実体重 − IBW)
- CCr から腎機能区分（>50 / 10–50 / <10 / HD / CHDF）を解決し、薬剤詳細で該当行をハイライト・他行を淡色化
- HD/CHDF は CCr 区分より優先
- 原典に記載のない区分は補完せず「原典に記載なし」と表示

**再編で変わる点は1つだけ**: 患者条件パネルに `成人 / 小児` の別を持たせる。
年齢が入力されていれば自動判定し（15歳未満を小児とするか等の閾値は原典の記載に従い、
記載がなければ自動判定せず利用者選択とする — **要確認事項**）、
手動でも上書きできるようにする。未選択でもアプリは動作し、その場合は両方の用量を等価に並記する。

## 3. TDM導線の強化

### 現状

薬剤詳細 → TDM設計画面への遷移は**すでに実装済み**（`DrugDetail.tsx` の TDMセクション内、
`onOpenDesigner(drug.tdm.designer)`）。対象は5剤。

| 薬剤 | designer キー |
| --- | --- |
| バンコマイシン | `vancomycin` |
| テイコプラニン | `teicoplanin` |
| ゲンタマイシン | `aminoglycoside` |
| アミカシン | `aminoglycoside` |
| ボリコナゾール | `voriconazole` |

### 再編でやること

導線を「あることに気づける」ようにするのが主眼で、計算ロジックは触らない。

1. **詳細画面の上部に引き上げる。** 現在はページ下部のTDMセクション内にあり、スクロールしないと届かない。
   `TDM対象` バッジ自体を押せるようにし、ヘッダー直下から設計画面へ飛べるようにする。
2. **設計画面から薬剤詳細へ戻る導線を追加する。** 現在 `Designer` は薬剤への逆リンクを持たない。
   設計画面の冒頭に「◯◯の薬剤詳細を見る →」を置き、往復できるようにする。
3. **患者条件の引き継ぎを明示する。** 設計画面は `patient` を受け取るが、未入力だと計算できない項目がある。
   不足している入力（体重・eGFR等）を名指しで示し、その場で患者条件パネルを開けるようにする。
4. **アミノグリコシド2剤の区別。** GM と AMK が同じ `aminoglycoside` designer を共有している。
   どちらから来たかを引数で渡し、設計画面の見出しと用量表に反映する。

PCG持続静注は TDM ではなく調製手順のため、現行どおり独立ページに残す。

## 4. 表組みレイアウトの是正

### 原因（調査済み）

`src/styles.css` で全テーブルに単一クラス `table.abx` が使われており、そこに
`white-space: nowrap` が指定されている（styles.css:341-346）。

```css
table.abx th, table.abx td {
  padding: 7px 9px;
  border-bottom: 1px solid var(--rule-soft);
  text-align: left;
  white-space: nowrap;   /* ← 全9テーブルに一律で効いている */
}
```

これはアンチバイオグラム（数値％・略号のみ・折り返すと読めない）には正しいが、
**日本語の長い説明文を含む表に同じ指定が効いてしまい**、セルが折り返せず横に伸びる。
結果、列幅の配分が崩れ、横スクロールが必要になり読みにくくなっている。

該当箇所（`table.abx` を使う9テーブル）:

| ファイル | 用途 | 適切な型 |
| --- | --- | --- |
| `OrganismDetail.tsx` ×2 | アンチバイオグラム（数値） | 数値表（nowrap 維持） |
| `Reference.tsx:159,192` | 小児体重表・Von Harnack表（数値） | 数値表（nowrap 維持） |
| `Reference.tsx:68` | アナフィラキシー重症度・薬剤（説明文） | **文章表（折り返す）** |
| `Reference.tsx:432` | AWaRe分類（薬剤名・商品名） | **文章表（折り返す）** |
| `SurgicalProphylaxis.tsx:76,156` | 創分類・βラクタムアレルギー代替（説明文） | **文章表（折り返す）** |
| `Formulary.tsx:62` | 採用注射薬一覧（規格・注記・配合変化） | **文章表（折り返す）** |

### 対応方針

1. `table.abx` を **2クラスに分離**する。
   - `table.abx`（数値表）: `white-space: nowrap` 維持、`.scroll` で横スクロール、数値は `tabular-nums` 右寄せ
   - `table.doc`（文章表）: **折り返しあり**、`table-layout: fixed` + 列ごとの `width` 指定、
     `word-break: normal; overflow-wrap: anywhere`、行間を広げる
2. 文章表では**列幅を内容に応じて明示**する。自動配分に任せると、日本語は単語境界がないため
   極端な配分になりやすい。各表で列比率を決め打ちする（例: 創分類表 = 20% / 30% / 50%）。
3. **狭い画面では表をカードに落とす。** 480px未満では `table.doc` を
   「1行 = 1カード、列見出しをラベルとして各値の上に置く」レイアウトへ切り替える。
   横スクロールを利用者に強いない。主戦場がスマートフォンであるため、これは装飾ではなく可読性の要件。
4. `.kv`（定義リスト）の `grid-template-columns: auto 1fr` を見直す。
   `auto` は最長の `dt` に引きずられて左列が過大になる。`minmax(5.5em, max-content) 1fr` に改め、
   狭幅では1列積みへ落とす。

### 作成後の配置チェック（ご指示事項）

**実装後に必ず実施し、結果を報告する。** 目視の主観に頼らず手順化する。

- 本環境の Chromium + Playwright で、**幅 375px / 768px / 1280px** の3種でスクリーンショットを撮る。
- 撮影対象: 大項目4画面 + 表を含む7画面（アンチバイオグラム・採用薬一覧・周術期×2・
  アナフィラキシー・小児体重・AWaRe）
- 判定基準（1つでも該当したら不合格）:
  - `document.body` に横スクロールが発生している（`scrollWidth > clientWidth`）
  - 表のセルが1文字だけで折り返している列がある
  - ある列が表幅の70%以上を占めている
  - テキストが親要素からはみ出している
- スクリーンショットは成果物として提示し、目視でも最終確認する。

## 7. 未決事項（実装前に判断が必要）

1. **AWaRe のボタン数** — 4（ご指示どおり、Not recommended をどこかに寄せる）か
   5（Not recommended を独立させる、本書の推奨案）か。→ §1.2 の枠内参照
2. **小児の年齢閾値** — 年齢から成人/小児を自動判定してよいか。原典に閾値の明記があるか要確認。
   明記がなければ自動判定せず、利用者の明示選択のみとする（安全側）。
3. **成人・小児の並記に対する薬剤部レビュー** — §0 の安全性方針の変更について、
   実装後・公開前にレビューを受ける。ここが承認されるまで院内公開しない。
4. **大項目から漏れる薬剤の扱い** — 内服・注射どちらの用量も持たない薬剤が1剤ある。
   どのレーンにも現れないため、検索欄からのみ到達可能になる。データ側の欠落か仕様かを確認する。

## 8. 本計画で「やらないこと」

- 検索アルゴリズムの入れ替え（対象の絞り込みは行うが、マッチング処理は現行を流用）
