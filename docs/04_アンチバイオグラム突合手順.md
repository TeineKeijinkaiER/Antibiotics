# アンチバイオグラム 突合手順（目視照合）

- 版: 0.2
- 対象: `src/data/antibiogram.json`（入院・外来 各40行、計80行）
- 目的: アプリ収載値を原本と照合し、**一致したことを記録に残す**

---

## 0. なぜ突合が必要か

アプリのアンチバイオグラムは、原典PDF（p.70-71）から**テキスト抽出して再構成**したものである。
PDFの表はテキスト抽出すると列の区切りが失われ、どの数値がどの抗菌薬の列かが確定しない。

感受性率の取り違えは抗菌薬選択の誤りに直結するため、院内公開前に原本との照合が必須である。
アプリ内では `meta.verified: false` により全菌詳細に検証待ちバナーを表示している。
照合完了後にこれを `true` にすることでバナーが消える。

---

## 1. 進め方

作成元Excelの提供は受けられないため、**印刷したシートと原本を並べての目視照合**を本線とする。

| 手順 | 内容 | 実施者 | コマンド |
| --- | --- | --- | --- |
| ① 事前チェック | 機械で裏が取れる範囲を確定させ、目視で重点的に見るべき行を絞る | 開発 | `npm run antibiogram:check` |
| ② シート出力 | 原典と同じ列順・行順の照合シートを印刷 | 開発 | `npm run antibiogram:sheet` |
| ③ 目視照合 | 原本と1セルずつ照合し、✓と訂正を記入 | 感染制御管理室・検査部 | — |
| ④ 訂正反映 | 記入内容を反映し、再出力して再確認 | 開発 | `apply-corrections.mjs` |
| ⑤ 完了記録 | `meta.verified` を true にし、照合日・照合者を記録 | 開発＋確認者 | — |

---

## 2. 手順① 事前チェック（機械で裏が取れる範囲を確定する）

```bash
npm run antibiogram:check
```

### 何を検証しているか

total 行は「非ESBL株の行」と「ESBL株の行」の**検出株数による加重平均**で説明できるはずである、
という関係を使う。

```
予測値 = (n_非ESBL × S_非ESBL + n_ESBL × S_ESBL) ÷ n_total
```

たとえば S. aureus (total) の CEZ 67% は、MSSA の CEZ 100% × (1 − MRSA率 0.33) = 67% と一致する。
列がひとつでもずれていれば、この等式は成り立たなくなる。

### 現在の結果

```
検証した組: 12 ／ 検証したセル: 126
整合OK — 不整合 0 件 / 注意 4 件
```

126セルすべてで加重平均が一致した。よって次の **18行は列対応の信頼度が高い**。
目視でも確認するが、優先度は下げてよい。

- 大腸菌（3行：非ESBL／ESBL／total）／肺炎桿菌（3行）／K. oxytoca（3行）
- P. mirabilis（3行）／S. aureus（3行：MSSA／MRSA／total）／S. epidermidis（3行）
- 上記が入院・外来それぞれにある

### 目視でしか確認できない行（重点確認）

total 行を持たない菌は加重平均が使えず、**機械では一切検証できない**。
シート上で地色を敷いて区別している。

| グラム陰性桿菌・嫌気性菌 | グラム陽性球菌 |
| --- | --- |
| P. vulgaris、E. cloacae、K. aerogenes、C. freundii、S. marcescens、M. morganii、緑膿菌、Acinetobacter、B. fragilis、嫌気性GNR、H. influenzae | S. lugdunensis、その他CNS、E. faecalis、E. faecium、VGS、SAG、GAS、GBS、GGS、肺炎球菌（髄膜炎／非髄膜炎） |

入院・外来あわせて **44行が重点確認**の対象になる。

### 分母の確認が要るセル

感性率が「菌数分の整数」で作れない4セルが検出された。誤りとは限らず、
その抗菌薬の**被検株数が菌数と異なる**（全株では測定していない）場合に起きる。
シート上でピンクに着色しているので、原本で分母を確認する。

| 区分 | 菌 | 抗菌薬 | 収載値 | 菌数 | 最も近い値 |
| --- | --- | --- | --- | --- | --- |
| 入院 | G群溶血性レンサ球菌 | CLDM | 86% | 8 | 87.5% |
| 外来 | B. fragilis | CLDM | 60% | 31 | 61.3% |
| 外来 | E. faecium | PCG | 16% | 27 | 14.8% |
| 外来 | E. faecium | ABPC | 16% | 27 | 14.8% |

## 3. 手順② 照合シートを出力する

```bash
npm run antibiogram:sheet > checksheet.html
```

ブラウザで開き、**A4横・背景グラフィックあり**で印刷する（入院1枚・外来1枚）。

シートは原典 p.70-71 の表と**同じ列順・同じ行順**で並べてある。原本を隣に置いて
行を横に追えるようにするのが狙い。

| シート上の表示 | 意味 |
| --- | --- |
| 地色つきの行（左に縦線） | 算術整合チェックで裏が取れていない行 — **重点確認** |
| 白い行 | 加重平均で相互検証済みの行 |
| ピンクのセル | 菌数から作れない値 — 分母を確認 |
| グレーのセル | 空欄＝データなし（**0%ではない**） |
| ✓欄 | 行全体が一致したらチェック |
| 訂正欄 | 相違があれば正しい値を記入 |

ヘッダに照合日・照合者・確認者の記入欄がある。

### 照合時に特に見るところ

1. **空欄とゼロの区別** — アプリの空欄が原本では数値になっていないか。列の取り違えはここに現れる。
2. **列の位置** — 値そのものより、値が正しい抗菌薬の列に入っているかを見る。
   ひとつずれていると、行全体の値がもっともらしいまま全部間違う。
3. **菌数** — 各行の菌数が原本と一致するか。
4. **注記** — ESBL産生率・CRE率・MRSA/MRSE率が原本と一致するか。

## 4. 手順④ 訂正を反映する

シートの訂正欄に書いた内容を、次の形式のテキストファイルに書き写す。

```
# 区分  菌名                      項目   正しい値
入院    Pseudomonas aeruginosa    MEPM   85
入院    緑膿菌                     CAZ    -        ← - で「データなし（空欄）」にする
外来    E. faecium                菌数    28
```

- 区切りはタブ・カンマ・連続スペースのいずれでもよい
- 区分は「入院 / 外来」
- 菌名は学名・日本語名・略号のいずれでもよい（「黄色ブドウ球菌」のように複数の菌に当てはまる
  書き方はエラーになるので、MSSA / MRSA のように区別して書く）
- 項目は抗菌薬の略号、または「菌数」

```bash
# 確認だけ（ファイルは変更しない）
node scripts/apply-corrections.mjs corrections.txt

# 反映する
node scripts/apply-corrections.mjs corrections.txt --apply
```

出力例:

```
3 件の訂正:
  訂正　　 [入院 緑膿菌] MEPM: 88 → 85
  訂正　　 [入院 緑膿菌] CAZ: 89 → 空欄
  訂正　　 [外来 腸球菌（フェシウム）] 菌数: 27 → 28
```

現在値と同じ訂正は「変化なし」と表示される。書き写しのミスか、
既に反映済みかを確認すること。

### 反映後に必ず実行する

```bash
npm run validate                      # 値域・参照切れ・加重平均の再検査
npm run antibiogram:sheet > checksheet.html   # 訂正後のシートを出し直して再照合
```

**手順①を反映後にもう一度通すことが重要**で、訂正した結果として加重平均が崩れた場合、
訂正内容か元の値のどちらかに問題があることを意味する。

---

## 5. 手順⑤ 完了の記録

すべての行の照合が終わったら `src/data/antibiogram.json` の `meta` を更新する。

```jsonc
"verified": true,
"verificationNote": "2026-XX-XX、感染制御管理室・検査部により令和8年度アンチバイオグラム原本と全80行を目視照合し一致を確認。照合者：○○、確認者：○○"
```

これによりアプリ内の検証待ちバナーが消える。
`meta.verified` を `true` にする変更は必ずレビューを通し、誰がいつ確認したかを
コミット履歴に残すこと（要件 NFR-011）。記入済みの照合シートも保管する。

---

## 6. 年次改訂時

翌年度のアンチバイオグラムに差し替える際も同じ手順を使う。

1. `meta.verified` を `false` に戻し、`meta.year` / `meta.period` を更新する
2. 新しい値を `apply-corrections.mjs` で入れる（行数が変わる場合は `antibiogram.json` を直接編集）
3. 手順① → ② → ③ → ④ を通す
4. `meta.verified` を `true` に戻し、照合記録を書く

データのみの差し替えで済み、コード変更は不要である（要件 NFR-009）。

## 付録：Excelが入手できた場合

将来 CSV が用意できるなら、目視の前に機械突合を挟むと効率がよい。
`scripts/diff-antibiogram.mjs` が1セル単位の差分を出す（依存パッケージなし）。

```bash
node scripts/diff-antibiogram.mjs 入院.csv --setting inpatient          # 差分表示
node scripts/diff-antibiogram.mjs 入院.csv --setting inpatient --apply  # 反映
```

期待するCSVは原典と同じ横並びの形で、「菌数」を含む行をヘッダとして自動検出する。
菌名の表記ゆれ、`S/A`・`T/P` のような略記も解釈する。
ただし**機械突合はCSVとJSONの一致しか見ない**ため、Excelからの書き出しで列がずれていれば
両方とも同じように間違う。最終的な目視照合は省略できない。
