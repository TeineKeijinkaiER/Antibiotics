# アンチバイオグラム 突合手順

- 版: 0.1
- 対象: `src/data/antibiogram.json`（入院・外来 各40行、計80行）
- 目的: アプリ収載値を、感染制御管理室・検査部が作成した**原データと一致させ、一致したことを記録に残す**

---

## 0. なぜ突合が必要か

アプリのアンチバイオグラムは、原典PDF（p.70-71）から**テキスト抽出して再構成**したものである。
PDFの表はテキスト抽出すると列の区切りが失われ、どの数値がどの抗菌薬の列かが確定しない。

現状は後述の算術整合チェックで主要行の列対応を検証しているが、これは**間接的な裏取り**であり、
原本との一致を保証しない。感受性率の取り違えは抗菌薬選択の誤りに直結するため、
院内公開前に原データとの1セル単位の突合が必須である。

アプリ内では `meta.verified: false` により全菌詳細に検証待ちバナーを表示している。
突合完了後にこれを `true` にすることでバナーが消える。

---

## 1. 突合の3段階

| 段階 | 方法 | 原データの要否 | いつ実施 |
| --- | --- | --- | --- |
| A. 自己整合チェック | `check-antibiogram-consistency.mjs` | 不要 | 今すぐ／データ変更のたび |
| B. 機械突合 | `diff-antibiogram.mjs` | **必要**（CSV） | 原データ入手後 |
| C. 目視照合 | チェックシート出力 → 原本と照合 | 必要（原本の見た目） | Bの後、検査部が実施 |

A だけでは不十分、B だけでも不十分。A は total 行を持つ菌にしか効かず、B は
「Excelから正しくCSVを書き出せたか」を保証しないため、両方を通す。

---

## 2. 段階A — 自己整合チェック（原データなしで今すぐできる）

```bash
node scripts/check-antibiogram-consistency.mjs
```

### 何を検証しているか

total 行は「非ESBL株の行」と「ESBL株の行」の**検出株数による加重平均**で説明できるはずである、
という関係を使う。

```
予測値 = (n_非ESBL × S_非ESBL + n_ESBL × S_ESBL) ÷ n_total
```

たとえば S. aureus (total) の CEZ 67% は、MSSA の CEZ 100% × (1 − MRSA率 0.33) = 67% と一致する。
列がひとつでもずれていれば、この等式は成り立たなくなる。

あわせて次も検査する。

- 株数の整合（非ESBL + ESBL = total）
- 注記の割合（「ESBL産生菌の割合：17%」）と実際の株数比の一致
- 感性率が菌数分の整数で説明できるか（できない場合、その抗菌薬の被検株数が菌数と異なる可能性）

### 現在の結果

```
検証した組: 12 ／ 検証したセル: 126
整合OK — 不整合 0 件 / 注意 4 件
```

126セルすべてで加重平均が一致した。よってこの12組（大腸菌・肺炎桿菌・K. oxytoca・
P. mirabilis・S. aureus・S. epidermidis の入院/外来）の列対応は**信頼度が高い**。

注意4件は「感性率が菌数分の整数で作れない」もので、誤りとは限らない。
薬剤ごとに被検株数が異なる（全株で測定していない）場合に起きるため、
段階Bで分母を確認する。

| 菌 | 抗菌薬 | 収載値 | 菌数 | 確認事項 |
| --- | --- | --- | --- | --- |
| 入院 G群溶血性レンサ球菌 | CLDM | 86% | 8 | 8株なら12.5%刻み（87.5%が最近傍） |
| 外来 B. fragilis | CLDM | 60% | 31 | 31株なら3.2%刻み |
| 外来 E. faecium | PCG | 16% | 27 | 27株なら3.7%刻み |
| 外来 E. faecium | ABPC | 16% | 27 | 同上 |

### 段階Aで検証**できない**菌

total 行を持たない菌は加重平均が使えず、この方法では検証できない。
これらは段階B・Cでしか確認できない。

- 緑膿菌、アシネトバクター属、B. fragilis、嫌気性GNR、H. influenzae
- P. vulgaris、E. cloacae、K. aerogenes、C. freundii、S. marcescens、M. morganii
- S. lugdunensis、その他CNS、腸球菌（faecalis / faecium）
- レンサ球菌（VGS、SAG、GAS、GBS、GGS）、肺炎球菌（髄膜炎／非髄膜炎）

## 3. 段階B — 機械突合（原データ入手後）

### 3-1. 検査部にお願いすること

> 令和8年度アンチバイオグラム（入院・外来）の**作成元Excelから、入院用と外来用をそれぞれ
> CSV UTF-8（コンマ区切り）で保存**してください。レイアウトは変更不要です。
> PDF化する前の、感性率を計算しているシートをお願いします。

CSVは次の形であればよい。列の順序は問わない。

```
菌名,菌数,ABPC,PIPC,S/A,T/P,MEPM,CEZ,CMZ,CTRX,CAZ,CFPM,AMK,CLDM,CPFX,LVFX,ST
Escherichia coli,583,66,75,76,96,100,92,96,98,98,99,99,,78,73,91
Escherichia coli （ESBL）,122,,,34,93,100,,99,,,,98,,19,9,63
```

- 「菌数」を含む行を**ヘッダとして自動検出**するため、上に説明行があっても構わない
- 菌名は学名・日本語名・略号のいずれでもよい（`organisms.json` の別名で照合する）
- 空欄は「データなし」として扱う（0%とは区別する）
- `S/A`＝SBT/ABPC、`T/P`＝TAZ/PIPC のような略記も解釈する

### 3-2. 突合を実行する

```bash
# 差分を見るだけ（ファイルは変更しない）
node scripts/diff-antibiogram.mjs 入院.csv --setting inpatient
node scripts/diff-antibiogram.mjs 外来.csv --setting outpatient
```

出力例:

```
アンチバイオグラム突合（入院）
  照合できた菌: 40 ／ 比較したセル: 298 ／ 相違: 2

2 件の相違:
  差分  [大腸菌] ABPC: アプリ 66% / 原データ 64%
  差分  [大腸菌] SBT/ABPC: アプリ 76% / 原データ 79%
```

検出する相違は4種類。

| 種類 | 意味 |
| --- | --- |
| 値が違う | 転記ミス、または丸めの違い |
| アプリは空欄だが原データに値がある | 列の取り違えで値を落としている |
| アプリに値があるが原データは空欄 | **列の取り違えの可能性が高い**。最優先で確認 |
| 菌数が違う | 集計期間や対象の解釈違い |

菌名がマスタにない場合はエラーとして報告されるので、`organisms.json` の `aliases` に
検査部の表記を追加してから再実行する。

### 3-3. 差分を反映する

差分を確認し、原データが正であると判断できたら反映する。

```bash
node scripts/diff-antibiogram.mjs 入院.csv --setting inpatient --apply
node scripts/diff-antibiogram.mjs 外来.csv --setting outpatient --apply
```

反映後は必ず再実行して「相違なし」になることを確認する。

```bash
node scripts/diff-antibiogram.mjs 入院.csv --setting inpatient   # 相違なし になるはず
node scripts/check-antibiogram-consistency.mjs                    # 加重平均も再確認
npm run validate                                                  # 値域・参照切れの再検査
```

段階Aを反映後に再実行するのが重要で、**原データを入れた結果として加重平均が崩れた場合、
CSVの書き出し側に問題がある**ことを意味する。

## 4. 段階C — 目視照合（検査部が実施）

機械突合は「CSVとJSONの一致」しか見ない。Excelからの書き出し時に列がずれていれば
両者とも同じように間違う。最後に人の目で原本と突き合わせる。

```bash
node scripts/diff-antibiogram.mjs --export --setting inpatient > 突合シート_入院.csv
node scripts/diff-antibiogram.mjs --export --setting outpatient > 突合シート_外来.csv
```

出力はBOM付きUTF-8なのでExcelでそのまま開ける。印刷して原本と並べ、
**特に段階Aで検証できなかった菌**（§2末尾の一覧）を重点的に照合する。

照合が終わったら、シートに実施日・実施者を記入して保管する。

---

## 5. 完了の記録

すべての菌・区分の突合が終わったら `src/data/antibiogram.json` の `meta` を更新する。

```jsonc
"verified": true,
"verificationNote": "2026-XX-XX、感染制御管理室・検査部により令和8年度アンチバイオグラム作成元Excelと全80行を突合し一致を確認。実施者：○○、確認者：○○"
```

これによりアプリ内の検証待ちバナーが消える。
`meta.verified` を `true` にする変更は必ずレビューを通し、誰がいつ確認したかを
コミット履歴に残すこと（要件 NFR-011）。

---

## 6. 年次改訂時

翌年度のアンチバイオグラムに差し替える際も同じ手順を使う。

1. `meta.verified` を `false` に戻し、`meta.year` / `meta.period` を更新する
2. 新しいCSVで `--apply` を実行する
3. 段階A → B → C を通す
4. `meta.verified` を `true` に戻し、突合記録を書く

データのみの差し替えで済み、コード変更は不要である（要件 NFR-009）。
